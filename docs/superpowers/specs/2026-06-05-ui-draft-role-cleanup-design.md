# 界面细节、任免草稿与角色清理设计

## 目标

在不改变任免业务字段和现有部门权限边界的前提下，修复侧栏滚动条、分页中文、任免新增草稿生命周期和角色分配报错，并将系统角色统一为以下五种：

- `SUPER_ADMIN`
- `PARTY_HR_ADMIN`
- `PARTY_HR_USER`
- `GENERAL_ADMIN_ADMIN`
- `GENERAL_ADMIN_USER`

## 界面调整

`el-aside` 默认设置了 `overflow: auto`，侧栏收起按钮向右外伸后扩大滚动区域，导致底部出现横向滚动条。通过覆盖侧栏溢出样式为 `visible`，保留外伸按钮并消除滚动条。

任免看板分页使用 Element Plus 中文配置，分页总数显示为“总计 XX 条”，页容量显示为“XX条/页”。只调整分页文案，不改变分页请求参数和交互。

## 新增任免草稿

新增模式维护独立草稿：

- 第一次打开时使用空表默认值。
- 点击“取消”或右上角关闭按钮时仅关闭弹窗，草稿继续保留。
- 再次打开新增弹窗时恢复草稿。
- 保存失败时保留草稿。
- 保存成功时先清空草稿，再关闭弹窗并刷新看板。
- 查看和编辑已有记录不覆盖新增草稿。

## 角色模型

新增 Flyway `V5` 数据迁移：

- 将 `GENERAL_ADMIN_MANAGER` 原地重命名为 `GENERAL_ADMIN_ADMIN`，保留角色 ID 和已有权限、用户关系。
- 删除所有 `DEPARTMENT_USER` 用户关系和权限关系，再删除该角色。
- 既有普通账号保留对应部门的 `USER` 角色。

后端注册只绑定所属部门的 `USER` 角色。角色分配不再补齐隐藏基础角色，也不接受已删除角色。部门管理员仍只能管理本部门账号并分配本部门的管理员或用户角色。

## 验证

- 前端单元测试覆盖新增草稿关闭保留、保存成功清空和角色弹窗只提交可见角色。
- 后端单元与接口测试覆盖注册默认角色、五角色列表、管理员编码和角色分配。
- Flyway 迁移测试验证旧角色被重命名、`DEPARTMENT_USER` 被删除且用户角色关系正确。
- 浏览器验证侧栏无滚动条、分页中文、草稿恢复、保存关闭和角色分配。
