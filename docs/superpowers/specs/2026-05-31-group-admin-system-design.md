# 集团后台管理系统第一版设计说明

## 1. 目标与范围

第一版建设一个可部署上线的集团后台管理系统，采用前后端分离架构：

- 后端：Java、Spring Boot、MySQL。
- 前端：Vue 3、TypeScript、Element Plus。
- 部署：Docker Compose 编排 MySQL、Spring Boot 后端、Nginx + Vue 前端，并持久化数据库和上传文件目录。

第一版必须包含：

- 首页登录入口、账号注册入口，登录页背景基于 `素材/集团大门.png` 重新设计。
- 默认超级管理员账号：`superadmin`，初始密码：`xjyadmin`。系统初始化时写入该账号，数据库中只保存密码摘要。
- 注册账号字段：账号、密码、手机号、部门。部门为单选项：党群人力部、综合管理部。
- 登录后左侧菜单、右侧主功能区。
- 超级管理员可见菜单：党群人力部、综合管理部、设置；默认进入党群人力部看板。
- 普通账号仅可见其注册部门对应页面。
- 党群人力部看板包含员工任免表格和任免审批表详情/编辑/删除能力。
- 综合管理部第一版仅展示“功能开发中，敬请期待”。
- 设置页第一版提供用户查看和角色分配，仅超级管理员可访问。

第一版不包含复杂审批流、消息通知、组织树维护、导出打印、操作日志查询界面。这些能力通过当前模块边界预留扩展空间。

## 2. 架构选择

采用“模块化单体后端 + 前后端分离”的方案。

后端是一个 Spring Boot 应用，但内部按模块划分：

- `auth`：登录、注册、JWT、当前用户。
- `system`：用户、角色、权限、菜单、设置。
- `organization`：部门基础数据。
- `appointment`：党群人力部员工任免审批表。
- `file`：证件照等附件上传、访问和校验。
- `common`：统一响应、异常处理、分页、审计字段、逻辑删除。

这样第一版部署和排错成本较低，同时后续新增部门、看板、表单或审批流程时，可以在业务模块扩展，不需要推翻认证和权限底座。

## 3. 登录、注册与权限菜单

登录页以素材图片重新设计，不照搬原图版式。页面以登录为主，注册为辅助入口。

注册规则：

- 账号必填且唯一。
- 密码必填，后端加密保存。
- 手机号必填并校验格式。
- 部门必选，只能选择党群人力部或综合管理部。
- 注册用户默认授予普通部门用户角色，部门权限由注册时选择的部门决定。

登录规则：

- 后端校验账号状态和密码。
- 登录成功返回 JWT、用户信息、角色、部门、可访问菜单。
- 前端将用户信息和菜单保存到 Pinia，并按后端菜单动态渲染左侧导航。

权限规则：

- `superadmin` 角色可访问党群人力部、综合管理部、设置。
- 党群人力部普通用户只能访问党群人力部页面。
- 综合管理部普通用户只能访问综合管理部页面。
- 前端隐藏无权限菜单，后端接口仍必须按角色和部门做二次校验。

## 4. 党群人力部看板

党群人力部看板右侧主区域展示 Element Plus 表格。

表头顺序固定为：

- 姓名
- 电话
- 身份证号
- 职位
- 毕业院校
- 地址
- 操作

交互规则：

- 员工姓名以文字按钮形式展示。
- 点击姓名打开任免审批表弹窗的只读查看态。
- 操作栏固定展示“编辑”“删除”两个文字按钮。
- 点击“编辑”打开同一个任免审批表弹窗的编辑态。
- 只有编辑态允许修改字段、上传照片、保存数据。
- 点击“删除”弹出确认框；用户点击确认后调用删除接口。
- 删除采用逻辑删除，记录不再出现在列表中。

## 5. 任免审批表弹窗

任免审批表以 `素材/任免审批表.doc` 为依据校对。源文件包含 2 张表，第一张表 40 个单元格，第二张表 48 个单元格。前端实现时保留表格字段顺序、合并单元格、左侧分行标签和整体结构，但使用 Element Plus 可落地的组件呈现。

组件规则：

- 短文本字段使用 `el-input`。
- 日期字段使用 `el-date-picker`。
- 照片区域使用 `el-upload`。
- 简历、奖惩情况、年度考核结果、任免理由、呈报单位、审批机关意见、行政机关任免意见使用 `el-input type="textarea"`。
- 填表人一栏可编辑，使用 `el-input`。

已确认的表格内容调整：

- “出生年月”右侧格子删除“（岁）”，改为可编辑输入/日期组件区域。
- “熟悉专业有何专长”右侧格子删除“计算机”。
- “奖惩情况”右侧格子删除“无”。
- “审批机关意见”右侧多行文本默认值为“此表信息已认定”。
- “审批机关意见”删除“（盖章）”。
- “行政机关任免意见”删除“（盖章）”。
- 呈报单位、审批机关意见、行政机关任免意见格子的右下角放日期组件。

照片校验：

- 仅允许 JPG、JPEG、PNG。
- 文件大小建议限制为 2MB 以内。
- 校验图片比例接近一寸证件照比例。
- 保存时文件先入附件表，任免审批表主记录引用照片附件编号。

## 6. 综合管理部与设置页

综合管理部第一版只展示文本：

> 功能开发中，敬请期待

设置页第一版包含：

- 用户列表。
- 用户所属部门展示。
- 角色分配。

设置页仅超级管理员可见。普通部门用户不显示设置菜单，直接访问设置路由时由前端路由守卫拦截，后端接口也返回无权限。

## 7. 数据模型

建议使用以下数据表：

### 7.1 sys_user

用途：保存登录账号与用户基础信息。

关键字段：

- `id`
- `username`
- `password_hash`
- `phone`
- `department_id`
- `status`
- `last_login_time`
- `created_by`
- `created_at`
- `updated_by`
- `updated_at`
- `deleted`

### 7.2 sys_role / sys_permission / sys_menu

用途：保存角色、权限码和菜单定义。

关键字段：

- 角色编码、角色名称、启用状态。
- 权限编码、权限名称。
- 菜单名称、路由路径、排序、权限编码、启用状态。

菜单由后端返回，前端只负责渲染。

### 7.3 sys_department

用途：保存部门基础数据。

第一版初始化：

- 党群人力部
- 综合管理部

后续新增部门时扩展该表，并新增对应菜单和业务模块。

### 7.4 appointment_record

用途：保存任免审批表主记录。

列表摘要字段：

- 姓名
- 电话
- 身份证号
- 职位
- 毕业院校
- 地址

审批表字段：

- 性别、出生年月、民族、籍贯、出生地。
- 入党时间、参加工作时间、健康状况。
- 专业技术职务、熟悉专业有何专长。
- 全日制教育、全日制毕业院校系及专业。
- 在职教育、在职毕业院校系及专业。
- 现任职务、拟任职务、拟免职务。
- 简历、奖惩情况、年度考核结果、任免理由。
- 呈报单位、呈报单位日期。
- 审批机关意见、审批机关意见日期。
- 行政机关任免意见、行政机关任免意见日期。
- 填表人。
- 照片附件编号。

### 7.5 appointment_family_member

用途：保存家庭主要成员及重要社会关系。

关键字段：

- `appointment_record_id`
- `relationship`
- `name`
- `age`
- `political_status`
- `work_unit_and_position`
- `sort_order`

该表支持任意行数，前端可默认展示 6 行空白行。

### 7.6 sys_file

用途：保存附件元信息。

关键字段：

- 原始文件名
- 存储文件名
- 存储路径
- MIME 类型
- 文件大小
- 业务类型
- 业务编号
- 上传人
- 上传时间

## 8. 接口设计

接口统一以 `/api` 为前缀。

### 8.1 认证接口

- `POST /api/auth/register`：注册。
- `POST /api/auth/login`：登录。
- `GET /api/auth/me`：获取当前用户、角色、部门、菜单。
- `POST /api/auth/logout`：退出登录。

### 8.2 权限与菜单接口

- `GET /api/system/menus/current`：获取当前用户菜单。
- `GET /api/system/users`：用户列表。
- `PUT /api/system/users/{id}/roles`：分配角色。
- `GET /api/system/roles`：角色列表。

### 8.3 任免业务接口

- `GET /api/party-hr/appointments`：分页查询任免记录。
- `GET /api/party-hr/appointments/{id}`：查询任免详情。
- `POST /api/party-hr/appointments`：新增任免记录。
- `PUT /api/party-hr/appointments/{id}`：编辑任免记录。
- `DELETE /api/party-hr/appointments/{id}`：逻辑删除任免记录。

### 8.4 文件接口

- `POST /api/files/id-photo`：上传一寸证件照。
- `GET /api/files/{id}`：访问文件。
- `DELETE /api/files/{id}`：删除文件引用或附件。

## 9. 前端结构

建议目录：

- `src/api`：接口请求封装。
- `src/router`：静态路由与权限守卫。
- `src/stores`：用户、权限、部门状态。
- `src/layouts`：后台框架布局。
- `src/views/auth`：登录与注册。
- `src/views/party-hr`：党群人力部看板。
- `src/views/general-admin`：综合管理部文字提示页。
- `src/views/settings`：设置页。
- `src/components/appointment`：任免表相关组件。

关键组件：

- `AppLayout`：侧边栏、顶栏、内容区。
- `PermissionMenu`：后端菜单渲染。
- `AppointmentTable`：员工任免列表。
- `AppointmentFormDialog`：任免审批表弹窗。
- `AppointmentFormGrid`：任免审批表表格。
- `PhotoUploader`：一寸照上传校验。
- `RoleAssignDialog`：角色分配弹窗。

## 10. 部署设计

使用 Docker Compose 管理：

- `mysql`：MySQL 数据库，使用 volume 持久化。
- `backend`：Spring Boot 后端服务。
- `frontend`：Nginx + Vue 静态资源。
- `uploads`：证件照文件挂载目录。

部署入口：

- 外部只开放 Nginx 端口。
- Nginx 承载前端静态资源。
- Nginx 将 `/api` 反向代理到后端服务。
- 后端通过环境变量读取数据库地址、数据库密码、JWT 密钥、上传目录。
- 初始化 SQL 创建基础表、基础菜单、基础角色、两个部门和 `superadmin` 账号。

## 11. 错误处理与校验

前端：

- 表单必填项即时校验。
- 手机号、身份证号、文件类型、文件大小、照片比例前端先校验。
- 接口错误通过 Element Plus 消息或弹窗提示。
- 无权限路由跳转到默认可访问页面或无权限页。

后端：

- 统一响应结构。
- 统一异常处理。
- 登录失败不暴露账号是否存在的细节。
- 所有需要权限的接口校验 JWT。
- 业务接口校验角色和部门。
- 删除接口使用逻辑删除。

## 12. 测试策略

后端测试：

- 注册、登录、密码加密、JWT 校验。
- 默认 `superadmin` 初始化。
- 菜单权限返回。
- 部门权限拦截。
- 任免记录增删改查。
- 家庭成员明细保存。
- 文件上传格式、大小和比例校验。

前端测试：

- 登录页和注册页表单校验。
- 不同角色登录后的菜单差异。
- 超级管理员默认进入党群人力部看板。
- 普通用户只能进入本部门页面。
- 任免审批表查看态和编辑态差异。
- 删除确认交互。

端到端验证：

- 使用 `superadmin / xjyadmin` 登录，可以访问全部菜单。
- 注册党群人力部用户后，只能访问党群人力部。
- 注册综合管理部用户后，只能看到综合管理部文字提示页。
- 上传一寸证件照后，任免审批表可以正确回显。
- Docker Compose 启动后，前端、后端、MySQL、上传目录均可正常工作。
